## Безопасность (22.10.2026) — сделано и проверено

Было найдено 3 дыры, все закрыты и проверены живыми запросами:

1. **Пароль на публичной галерее не защищал.** Правило `shoots/{id}` читалось всеми при
   `public == true` — аноним получал и `password`, и все `fileUrls` напрямую из Firestore
   (проверено: HTTP 200, `fileUrls_exposed=169`).
   Теперь: `shoots` читает только владелец, публичная галерея идёт только через серверный
   `/api/public-shoot`, который проверяет пароль на сервере.
2. **Лид-форма лендинга не писала лиды** — правило требовало авторизацию, посетитель не
   залогинен (403). Теперь анонимное создание разрешено с валидацией полей.
3. **`/api/delete-image` и `/api/delete-shoot` не проверяли права** — зная email + shootId,
   любой стирал папку фотографа в Cloudinary. Теперь требуется ID-токен владельца,
   а папка вычисляется из проверенного shootId.

Дополнительно: кэш `aiDescriptions` закрыт от клиентов, читает только сервер.

## Что сделано

- Публичная галерея `/public-gallery/$id` переделана: одна шапка, без навигации приложения, без «Войти»
- Клиент получает только доступ к одной сессии: просмотр, лайтбокс, скачивание фото и ZIP
- AI-оценки на клиентской галерее скрыты
- title сессии переименовывается в кабинете; если пусто — фоллбэк `Съёмка #xxxxxx`
- Пароль клиентски: кнопка «Поделиться» + кнопка копирования пароля внутри поля пароля
- Карточка: переключатель «Открыть доступ», пароль, ссылка; при выключенном доступе пароль и ссылка неактивны
- Защита от дублей при загрузке: один `shootId`, один документ в Firestore
- getUserShoots фильтруется по `userId`, чтобы не читать всю коллекцию
- Аудит дублей: `/audit-duplicates` показывает группы с одинаковыми `fileUrls`
- **Серверный доступ к Firestore: `src/lib/firestore-admin.ts`** — самоподписанный JWT + REST API,
  обходит правила. Заменяет firebase-admin, который ломал ESM-бандл Vercel
  (`__dirname is not defined in ES module scope`)
